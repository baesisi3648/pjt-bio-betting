## 2. 규칙 — `src/game/`

### 2-1. 경주 생성기 (`planRace` 교체)

```
입력: rng, trackCells=20, rounds=10
출력: { truth[8], lastRound (9|10), moves[동물][10] (각 0~3) }
```

조건 (전부 게이트로):
1. `truth` 는 무작위 순열. `rankByPosition(positions(10라운드), truth)` 가 `truth` 와 같다
2. 각 이동량 0~3, 각 라운드 합은 자유
3. 1위: 도달 라운드 ∈ {8, 9}. 도달 뒤 0
4. 2위: 도달 라운드 ≥ 1위 도달 라운드, ≤ 10. 3위: ≥ 2위, ≤ 10. `lastRound` = 3위 도달 라운드 (9 또는 10)
5. 4~8위: 10라운드 끝에 20 미만, **서로 다른 위치** (같으면 truth 로 tie-break 되지만 화면에서 겹친다 — 피한다)
6. 변칙: 10라운드 중 **선두가 최소 2번 바뀐다**, 1위 동물이 **3라운드 이후에 선두에 처음 선다**(초반 선두 아님) — 조건을 못 만족하면 다시 굴린다 (지금 `LIMITS.reverseAttempts` 방식)
7. 같은 시드면 같은 결과

`positionsAtRound`·`rankByPosition`·`computeOdds`·`settle` 는 그대로. `validateBet` 에 **골인 동물 거부**(`BET_FINISHED`)를 더한다 — 현재 위치가 `trackCells` 이상인 동물.

### 2-2. 힌트 — 라운드×난이도 30개

`buildHints(truth, names, rng)` → `Record<Level, string[10]>` 와 `buildHintPredicates` 짝. 라운드 r 의 난이도 L 힌트는 `hints[L][r-1]`.

- 문장 틀 (사용자 확정, 난이도별 5종). 한 판 안에서 같은 문장 중복 없음, 10개는 틀을 골고루 섞어 쓴다:
  - **쉬움**: "X는 1~4등 안에 듭니다" · "X는 1~4등 안에 들지 못합니다" · "X는 1등이 아닙니다" · "X는 꼴찌가 아닙니다" · "X와 Y 중 적어도 하나는 1·2·3등 안에 듭니다"
  - **보통**: "X는 Y보다 앞입니다" · "X는 Y와 Z 둘 다보다 앞입니다" · "X와 Y는 등수 차이가 3 이상입니다" · "X와 Y 사이에 정확히 한 마리가 있습니다" · "1등은 X도 Y도 아닙니다"
  - **어려움**: "1등은 X 또는 Y입니다" · "X는 2등 또는 3등입니다" · "X는 Y 바로 앞입니다" · "1·2·3등 안에 X와 Y가 모두 있습니다" · "X는 정확히 n등입니다" (**n은 4~8만** — 1~3등을 바로 주지 않는다)
  - 각 틀마다 `buildHintPredicates` 논리식이 짝으로 있어야 한다 (H2·H3 게이트)
- **모든 참 힌트는 참** (H2·H3 게이트 유지). 참 힌트 27개를 다 모아도 순위가 **유일하게 결정되지 않아야** 하는 것은 요구하지 않는다 — 대신 어려움 힌트 10개만으로 1~3등이 확정되지 않게 (게이트: 어려움 10개 논리식을 만족하는 순열이 2개 이상)
- **사기 라운드**: `fraudRound ∈ {2,3,4}` (스위치 켰을 때). 그 라운드의 3개는 같은 틀로 만들되 **논리식이 거짓**인 문장. 게이트: 그 3개 논리식은 truth 에서 false, 나머지 27개는 true
- `hintGiven` 은 이제 필요 없다 — 힌트는 (라운드, 난이도)로 결정된다. 대신 `answered[round].level` 로 어떤 힌트를 받았는지 안다. `takeHint` 삭제

### 2-3. 상태

`GameState` 변경: `className` → `roomTitle`, `unit` → `setName | null`, `fraudEnabled: boolean`, `fraudRound: number | null` (비공개 — truth 와 같은 등급), `hintPool: Record<Level, string[10]>`, `hintGiven` 삭제, `settings.rounds = 10`(고정이지만 상태에 둔다), `trackCells = 20`.
뷰: `teamView.fraudNotice: boolean`(스위치 켬 여부만 — 어느 라운드인지는 절대 아님), `teacherView.fraudRound`는 **정산 전 null**, `isOver` 뒤에만. 정산 화면에서 "3라운드가 거짓이었습니다" 공개.

### 2-4. 유지되는 불변식

MIGRATION §4-1(정답 비공개 — `fraudRound` 포함), §4-2, §4-4~§4-8 그대로. §4-3 은 "참 힌트 27개는 참, 사기 3개는 거짓" 으로 바뀐다.

## 3. 문제은행

### 3-1. D1 ✅ (2단계 완료)

- `questions`: `unit` → `set_name`(RENAME COLUMN, `migrations/0006_sets.sql`). `level` 값 '중간' → '보통'은 `0005` 가 했다. 기존 54문항은 세트 이름 = 예전 단원 이름 그대로 (0006 에 UPDATE 가 한 줄도 없다 — 이름만 바꾸고 값은 안 옮긴다)
- 인덱스도 `questions_unit` → `questions_set (set_name, level)`. `games.unit` → `set_name` 도 같이
- 세트 목록 = `SELECT set_name, level, COUNT(*) … GROUP BY set_name, level ORDER BY MIN(id)` 한 번 (문제은행에 들어온 순서를 지킨다 — 이름순으로 하면 문항 하나 고칠 때마다 드롭다운 순서가 뒤바뀐다)
- 방 만들 때 세트 하나 또는 **전체**. 전체면 `prepareSet(null)` 이 WHERE 없이 읽고, `games.set_name` 에는 `'(전체)'` 가 적힌다 (`bank.ts` 의 `ALL_SETS`)
- 문항 부족 경고 기준: `LIMITS.minHintsPerLevel`(6) → **`LIMITS.minQuestionsPerLevel`(10)**. 10인 이유는 라운드가 10개라서다 — 한 모둠이 10라운드 내내 같은 난이도를 고르면 그 난이도 10문항을 다 쓴다
- `settings` 기본값: moveSeconds 15, quizSeconds 40, discussSeconds 90, betSeconds 45, trackCells 20 (`0005`). `rounds` 는 설정에 두지 않는다 (`config.ts ROUNDS` = 10 고정), `fraudEnabled` 는 방마다 스위치라 설정이 아니다

### 3-2. JSON 형식 (애니멀 더비 공식)

```json
{
  "title": "세포와 물질대사 총정리",
  "questions": [
    {
      "difficulty": "easy",
      "question": "세포막의 주요 성분으로 가장 적절한 것은?",
      "choices": ["셀룰로스", "인지질", "녹말", "글리코젠"],
      "answer": 2,
      "explanation": "인지질 2중층이 세포막의 기본 골격이다."
    }
  ]
}
```

- `difficulty`: `easy | medium | hard` (내부 쉬움/보통/어려움). `answer`: 1~4. `explanation` 선택. `id` 는 내보낼 때 붙이고 가져올 때 무시
- 가져오기: 파일을 읽어 **요약(총·난이도별 개수, 오류 줄)** 을 먼저 보여주고 → **기존 세트에 추가 / 같은 이름 세트 교체 / 전체 교체** 중 선택. 형식 오류는 줄 번호와 이유
- 내보내기: 세트 하나 또는 전체를 위 형식으로. 파일명 `애니멀더비_{세트}_{날짜}.json`

**구현 (`src/server/portable.ts` — 런타임을 모르는 순수 함수라 게이트가 그대로 돈다)**

- 검사 순서(먼저 걸리는 하나만 사유로 준다): `type` ≠ `multiple_choice` → `question` 빈칸 → `choices` 4개·빈칸 없음 → `answer` 1~4 → `difficulty`
- `difficulty` 는 `easy|medium|hard`. **한국어('쉬움·보통·어려움')도 받는다** — 손으로 만든 파일이 대부분이다. 대응은 `LEVELS` 와 **자리(index)** 로 묶여 있어서 난이도 이름이 또 바뀌어도 따라간다
- `id` 는 내보낼 때 `q001` 식으로 붙이고 **가져올 때 무시한다.** 되받아 쓰면 "이미 있는 문항을 덮어쓸지" 라는 규칙이 하나 더 는다
- 잘못된 문항은 **건너뛰고** `errors[{index, reason}]` 로 모은다 (`index` 는 0부터, 화면이 +1 해서 "3번째 문항"). 파일 자체가 형식이 아닐 때(`questions` 가 배열이 아님)만 통째로 거절
- **유효한 문항이 0개면 `BAD_REQUEST` 로 막는다.** 안 막으면 `replaceAll` 이 문제은행을 비우고 끝난다
- 쓰기는 **D1 `batch` 한 번**(지우기 + 넣기). 두 번의 왕복으로 나누면 사이에 실패했을 때 은행이 빈 채로 남는다
- ⚠️ **전체 내보내기는 세트 경계를 잃는다.** 형식에 문항별 세트 칸이 없어서 한 파일의 `title` 이 `(전체)` 하나다. 세트를 지키려면 세트마다 한 번씩 내보낸다 (임의 결정 — 형식을 §3-2 그대로 두는 쪽을 골랐다)

### 3-3. 관리 화면 ✅ (2단계 완료)

`/admin` 그대로. 제목만 **"애니멀 더비 — 문제 관리자"**, '단원' → '문제 세트'.

- 상단 툴바: 세트 선택(— 전체 — / 각 세트) · `이름 바꾸기` · `세트 삭제` · `📥 JSON 가져오기` · `📤 JSON 내보내기` · `＋ 새 문제`
- 가져오기: `<input type=file accept=.json>` → 읽어서 `/import/preview` → **요약 카드**(파일명, 세트 이름, 총 N, 난이도별 알약 3개, 오류 목록 "3번째 문항: 보기 2개가 비어 있어요") → `기존 문제에 추가` / `같은 이름 세트 교체` / `전체 교체`(빨강 + 확인 대화) → 토스트 + 목록·건강 표 갱신
- 내보내기: **`<a href>` 가 아니라 `fetch`.** 그 파일에는 정답이 전부 들어 있어 관리자 헤더가 필요하고, 링크에는 헤더를 실을 수 없다. 받아서 `Blob` → `URL.createObjectURL` → 클릭. 파일 이름은 서버가 `content-disposition: filename*=UTF-8''…` 로 준다 (화면이 이름 규칙을 따로 갖지 않게)
- 건강 표: 세트별 쉬움/보통/어려움 개수, **10 미만이면 노란색 + ⚠️**, 각주 "난이도마다 10문항 이상이면 10라운드 동안 같은 문제가 안 나옵니다"
  - ⚠️ 표 아래 문장으로는 **문항 부족을 반복하지 않는다** (`summary` 가 `prep.skipped` 만 보낸다). 세트마다 세 줄씩 쌓이면 정작 읽어야 할 "12번 문항은 난이도가 이상해서 안 쓰입니다" 가 묻힌다
- 상단 고정 안내문("여기서 고친 것은 새로 만드는 방부터")은 그대로. 동물·설정 탭도 그대로

### 3-4. 라우트 (2단계에서 생기거나 바뀐 것)

**인증 없음**

| 경로 | 응답 `data` |
|---|---|
| `GET /api/sets` | `{sets:[{name, total, byLevel}]}` — **개수만.** 문제도 정답도 없다 (게이트 `LEAK-ADMIN`) |
| `GET /api/units` | `{units:[이름…], recent, recentError}` — **이름 그대로 둔다.** 교사 화면이 이 이름으로 읽고 있고 그 화면은 3단계 몫이다. `/api/sets` 와 같은 목록 |
| `GET /api/prepare?set=X` | `{blocking, warnings, units, sets}`. `?unit=` 도 받는다. **비면 전체 은행**(예전에는 빈 결과였다) |
| `POST /api/game` | `setName`(또는 `unit`)이 없거나 `''` 면 **전체 은행**. `games.set_name` 에는 세트 이름 또는 `'(전체)'` |

**관리자 (`X-Admin-Password` 를 매 호출)** — 전부 `router.ts` 의 `adminDenied` 를 지난다

### 4-2. 교사 진행 화면 — 5구획 ✅ 4단계 완료

1. **헤더**: 애니멀 더비 · 방 제목(길면 줄임표) · 🎭 사기 라운드 배지 | 라운드 진행표 `① ② ③ ④ ⑤ ● ⑦ ⑧ ⑨ ⑩` (현재 강조, 지난 라운드 채움) | ⏸ 일시정지 · ⏩ 빠른 진행(= 지금 넘어가기) · 🎵 · **⛶ 전체화면**(F 키)
2. **트랙**: 20칸, **좌→우**, START(왼쪽)·GOAL(오른쪽), 초록 잔디 + 흰 레인 경계 + 울타리, 약한 원근(위 레인이 살짝 좁게) — **위치 가독성이 우선.** 이모지는 `scale.x = -1` 로 반전, 레인 높이는 **남는 높이를 채운다**(아래 "한 화면 모드" — 1080p 에서 3모둠이면 ≈ 66px, 8모둠이면 ≈ 60px; 상한 90px). 골인 표시만, 등수 없음. PixiJS 무대·CSS 폴백·폰 미니 트랙 **셋 다 같은 방향**
3. **동물 현황 (한 줄 8카드)**: 번호·이모지·이름·**현재 순위**(현 위치 기준, 정산 전 최종 순위 아님)·배당률·판돈. **모둠별 베팅 없음**
4. **모둠 현황 (가로 카드)**: 이름 · 문제(풀이 중/제출·정답 여부는 **안 보임**, 제출만) · 베팅 확정 여부 · 남은 코인. **어느 동물인지 없음**
5. **하단**: `▶ ROUND n 시작`(크게) · 결과 확인(정산) · 학생 주소·암호 · 정답 순위 보기

**한 화면 모드** (2026-09-07 — "교사화면을 한 화면에 다 나오게"): 진행 화면은 **스크롤이 없다.** 다섯 구획을 세로 grid 로 두고 트랙만 남는 높이를 채운다. 배치는 언제나 1920×1080 기준으로 하고 실제 화면 높이에 맞춰 `zoom` 한다 — 1366×768 노트북을 미러링해도 1080p 와 같은 그림이 작게 나온다. 창이 아주 작으면(폭 900·높이 500 미만) 모드를 풀고 스크롤한다. 모둠이 여섯을 넘으면 모둠 카드가 두 줄(이름·코인 / 제출·베팅)로 접힌다. S1·배포 안내·정산 화면은 그대로 스크롤 화면. (`teacher.css` "한 화면 모드" · `main.ts applyFit` · `stage.ts build` 의 `hostH`)
