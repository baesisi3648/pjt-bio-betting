## 1. 게임이 무너지는 것부터 (제일 중요)

이 넷 중 하나라도 깨지면 수업에서 게임을 못 쓴다.

| # | 확인할 것 | 방법 | 통과 기준 |
|---|---|---|---|
| G1 | 최종 도착 순서 = 정답 순위 | `Test.gs`에서 판 100개 생성 후 6라운드 다 굴려 비교 | **100/100 일치** |
| G2 | 모든 힌트가 참 | 판 100개, 생성된 힌트 전부를 정답 순위에 대조 | 거짓 힌트 **0개** |
| G3-a | 전체 힌트로 1·2·3등을 좁힐 수 있다 | 판 100개, 전체 힌트를 합쳐 8! 순열을 걸러냄 | 1·2·3등이 유일하게 결정 **100/100** |
| G3-b | **어려움만 6번 고른 모둠**이 좁힐 수 있다 | 그 모둠이 받을 힌트 6개만으로 같은 검사 | 1·2·3등을 좁힐 수 있음 **100/100**. 안 되면 어려움을 고를 이유가 없다 (리뷰 반영) |
| G4 | 모둠 응답에 정답이 안 담김 | `toTeamView` 결과 JSON을 문자열로 만들어 검사 | `truth`·`moves`·`lastRound` 문자열 **0회 등장** |

G1이 이 프로젝트의 최대 위험이다. PDF 원본 코드가 바로 여기서 깨져 있었다.

## 3. 동시에 몰릴 때

| # | 상황 | 통과 기준 |
|---|---|---|
| C1 | 6모둠이 같은 순간 베팅 확정 | 동물별 누적 코인 합계가 어긋나지 않음 |
| C2 | 6모둠 동시 제출 + TV 폴링 | 모든 요청이 10초 안에 응답 |
| C3 | 잠금 대기 초과 | `LOCK_TIMEOUT`이 뜨고 화면에 안내가 나옴 (조용히 실패하지 않음) |
| C4 | 폰 6대 + TV 1대 2초 폴링 | 상태 조회 평균 응답 **0.3초 이하** |

C1은 실제 폰 6대로 "하나 둘 셋" 하고 동시에 눌러 확인한다.

## 4. 끊기고 복구되는 것

| # | 상황 | 통과 기준 |
|---|---|---|
| B1 | 모둠 폰 새로고침 | 판코드+모둠+암호 재입력으로 힌트·코인 그대로. **점유 때문에 막히지 않음** |
| B1-b | 같은 모둠에 폰 2대 동시 접속 | 둘 다 들어가지고 상태가 같음 (점유를 두지 않기로 함) |
| B2 | 폰 비행기모드 30초 후 복귀 | 자동으로 상태 따라잡음 |
| B3 | 교사 노트북 브라우저 종료 후 재접속 | 판 코드로 마지막 라운드 시작 시점부터 복구 |
| B4 | **라운드 중간에** 캐시 강제 삭제 후 조회 | 스냅샷 + `기록` 탭 사건 재생으로 **손실 0** — 그 라운드 답과 베팅이 전부 살아 있어야 함 |
| B5 | 1차시 종료 → 다음 날 2차시 이어하기 | 코인·힌트·베팅·트랙 위치 전부 그대로 |
| B6 | 일시정지 → 3분 후 재개 | 멈춘 지점의 남은 시간부터 이어감. 멈춘 동안 제출은 `PAUSED`로 거부 |

**B5가 이 프로젝트의 두 번째 위험이다.** 2차시 분할이 안 되면 기획 전체가 무너진다.

## 5. 시트가 잘못됐을 때

| # | 상황 | 통과 기준 |
|---|---|---|
| S1 | 어려움 문항 2개뿐 (6 필요) | 판 만들기 전 경고, 계속/취소 선택 가능 |
| S2 | `동물` 탭이 7줄 | 시작 불가 + 어디가 문제인지 안내 |
| S3 | `힌트문구`에서 `{X}`를 지움 | 시작 불가 + 몇 번째 줄인지 안내 |
| S4 | 난이도를 `상/중/하`로 적음 | 그 줄은 무시, 문항 수 경고에 반영 |
| S5 | 정답 열에 5를 적음 | 그 줄은 무시 + 안내 |
| S6 | 문제 0개인 단원 선택 | 시작 불가 |

## 7. 수업 전 점검표 (매 수업, 5분)

> 이건 코드 검사가 아니라 **선생님이 수업 직전에 하는 확인**이다. 이 목록을 앱 시작 화면에도 넣는다.

- [ ] 코드를 고쳤다면 **새 버전으로 재배포**했는가 (제일 흔한 사고)
- [ ] 화면 하단 배포 버전이 오늘 것인가
- [ ] 이번 단원 문항이 18개 이상인가
- [ ] 교사 노트북에서 학생 주소가 열리는가
- [ ] **내 폰(학교 와이파이)에서 학생 주소가 열리는가** ← 학교망 차단 확인
- [ ] 모둠별 암호를 인쇄했는가
- [ ] TV에 화면이 잘리지 않고 뜨는가

## 8. 첫 수업에서 볼 것

첫 판은 검사가 아니라 **관찰**이다.

| 볼 것 | 어긋나면 |
|---|---|
| 접속에 몇 분 걸리나 | 10분 넘으면 1차시 라운드를 2개로 줄임 |
| 문제 90초가 맞나 | 남으면 줄이고, 모자라면 늘림 (`설정` 탭에서 바로) |
| 베팅 60초가 맞나 | 같음 |
| 힌트로 실제 추론이 되나 | 너무 어려우면 어려움 힌트 비중을 늘림 |
| 하위권 모둠이 포기하나 | 포기하면 정산 규칙 완화를 재검토 (지금은 PDF 그대로) |
| **초반에 코인을 안 쓰고 버티나** | 최종 배당률만 쓰기로 한 결과. 다들 마지막에 몰빵하면 `01-prd §6-2`의 (가)~(다) 중 하나로 조정 |
| 배당률이 너무 튀나 | 시드 15가 여전히 낮으면 20으로, 밋밋하면 10으로 (`설정` 탭) |
| 폰 1대를 한 명이 독점하나 | 독점하면 모둠 메모장을 `Must`로 올리거나 A4 병행을 수업 규칙으로 |
| 옆 모둠 답을 베끼나 | 같은 문제를 주기로 한 결과. 심하면 모둠별 다른 문제 배정으로 전환 (문항 3배 필요) |
| 조용하던 학생이 말하나 | **이게 안 되면 기획 자체를 다시 본다** |
