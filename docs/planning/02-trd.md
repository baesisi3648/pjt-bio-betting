# 02. 기술 정의 — 무엇으로 어떻게 만드나

- 상위 문서: `01-prd.md`
- 확정된 방식: **구글 앱스 스크립트 + 속도 보강** (기획 대화에서 "2번" 선택)

## 1. 전체 그림

```
┌────────────────────────────────────────────────────────────┐
│  교사 노트북 → 교실 TV                                       │
│  [교사 화면] 트랙 / 배당률 전광판 / 모둠 진행 현황 / 라운드 제어  │
└───────────────┬────────────────────────────────────────────┘
                │ 2초마다 상태 요청
                ▼
┌────────────────────────────────────────────────────────────┐

│  ┌──────────────────────────────────────────────────────┐  │
│  │ 통신 계층 (GameGateway) ← 나중에 갈아끼울 수 있게 분리   │  │
│  ├──────────────────────────────────────────────────────┤  │
│  │ 게임 규칙 (순위 확정 / 이동 역산 / 힌트 생성·검산 /      │  │

│  ├──────────────────────────────────────────────────────┤  │
│  │ 임시보관함 CacheService  ←── 평소엔 여기서 읽음 (0.05초) │  │
│  │ 잠금장치 LockService     ←── 동시 베팅 순서 꼬임 방지     │  │
│  └────────────────────┬─────────────────────────────────┘  │
└───────────────────────┼────────────────────────────────────┘
                        │ 상태가 진짜 바뀔 때만
                        ▼
              ┌──────────────────────┐
              │ 구글 스프레드시트      │
              │ 문제 / 힌트문구 / 동물 │
              │ 게임상태 / 기록        │
              └──────────────────────┘
                        ▲
                        │ 2초마다 상태 요청
        ┌───────────────┴───────────────┐
        │ 모둠 폰 ×5~6                   │
        │ [모둠 화면] 문제 / 힌트 / 베팅  │
        └───────────────────────────────┘
```

## 2. 왜 앱스 스크립트인가 (그리고 왜 파이어베이스가 아닌가)

| 항목 | 앱스 스크립트 + 캐시 (채택) | 외부 서비스 (탈락) |
|---|---|---|
| 설치 | 없음 | 가입·프로젝트 생성·배포 학습 필요 |
| 비용 | 무료 | 무료 한도 있음, 초과 시 유료 |
| 계정 | 학교 구글 계정 | 학교 계정 밖 |
| 문제 관리 | 시트가 곧 저장소 — 부품 1개 | 시트 + 외부 DB + 동기화 장치 — **부품 3개** |
| 반응 속도 | 1~2초 | 0.1초 |
| 고장 났을 때 | 고칠 곳 한 군데 | 고칠 곳 두 군데 |

**결정 근거**: 이 게임에서 실시간이 필요한 순간은 베팅 60~90초 동안 배당률이 움직이는 것뿐이다. 모둠이 폰에서 베팅을 누르고 고개 들어 TV를 보는 데 이미 2초가 걸리므로, 1~2초와 0.1초는 교실에서 구분되지 않는다. 반대로 외부 서비스를 쓰면 관리할 곳이 두 배가 되는데, 수업 5분 전 고장을 혼자 고쳐야 하는 상황에서 이건 큰 손해다.

**단, 후퇴로를 남긴다**: 아래 §4의 통신 계층을 분리해 두어, 나중에 실시간이 정말 필요해지면 그 부분만 교체하고 게임 규칙·화면은 손대지 않는다.

## 3. 쓰는 것

| 구분 | 무엇 | 용도 |
|---|---|---|
| 서버 | Google Apps Script (V8 런타임) | 게임 규칙 전부. 순위·힌트·정산은 **서버에서만** 계산 |
| 화면 | HtmlService + 순수 HTML/CSS/JS | 외부 라이브러리 없음. 학교망 차단·오프라인 CDN 문제 회피 |
| 저장 | Google Sheets | 문제은행 + 게임 상태 + 기록 |
| 캐시 | CacheService (스크립트 범위) | 게임 상태 JSON을 최대 6시간 보관 |
| 잠금 | LockService | 동시 베팅·동시 제출 순서 보장 |
| 통신 | `google.script.run` | 화면 ↔ 서버 |

**의도적으로 안 쓰는 것**: React·Vue 같은 프레임워크, CDN에서 불러오는 라이브러리, npm 빌드 과정. 앱스 스크립트 편집기에 복사해 넣으면 바로 도는 상태를 유지한다 — 선생님이 직접 고칠 수 있어야 하기 때문.

## 4. 통신 계층 분리 (교체 가능하게)

화면 쪽 코드는 아래 함수들만 부른다. 이 이름과 주고받는 모양이 계약이다.

```js
// 화면이 부르는 함수 — 이 목록 밖으로 서버를 직접 부르지 않는다
GameGateway.createGame(config)              // 판 만들기 → { code }
GameGateway.joinGame(code, teamNo, pin)     // 모둠 접속 → { ok, teamState }
GameGateway.getState(code, viewer)          // 상태 조회 (2초 폴링)
GameGateway.submitAnswer(code, teamNo, difficulty, choice)
GameGateway.placeBet(code, teamNo, bets)    // { animalId: coins }
GameGateway.advanceRound(code)              // 교사 전용
GameGateway.togglePause(code)               // 교사 전용 — 일시정지 / 재개
GameGateway.finalize(code)                  // 교사 전용 → 정산 결과
```

`viewer`는 `"teacher"` 또는 `"team:3"`. **서버는 요청자에 따라 다른 내용을 돌려준다** — 모둠은 자기 힌트만 받고, 다른 모둠 힌트와 정답 순위는 응답에 아예 담기지 않는다. (화면에서 숨기는 게 아니라 보내지 않는다. 개발자 도구로 훔쳐보는 걸 막기 위함.)

나중에 실시간으로 바꾸려면 이 7개 함수의 속만 갈아끼우면 된다.

## 5. 속도 설계 — 앱스 스크립트 한계를 넘기

### 문제

시트 읽기·쓰기는 한 번에 0.5~2초 걸린다. 폰 6대 + TV 1대가 2초마다 상태를 물으면 초당 3.5회 요청이고, 매번 시트를 읽으면 줄이 밀린다.

### 해법

```
읽기 요청 들어옴
  → 임시보관함(CacheService)에 게임 상태 JSON이 있나?
      있음 → 그대로 반환 (0.05초)  ★ 거의 모든 요청이 여기
      없음 → 시트에서 읽어 임시보관함에 넣고 반환 (1~2초, 판당 몇 번뿐)

쓰기 요청 (베팅·답 제출·라운드 넘김)
  → 잠금장치 획득 (최대 10초 대기)
  → 임시보관함의 상태를 고쳐 다시 넣음
  → ★ 되돌릴 수 없는 사건은 `기록` 탭에 한 줄 즉시 추가 (0.2~0.4초)
  → 라운드가 끝나면 상태 전체를 `게임` 탭에 저장
  → 잠금 해제
```

- 게임 상태 JSON 하나를 통째로 캐시에 넣는다 (크기 약 5~15KB, 캐시 한도 100KB 안쪽)
- **상태 전체 쓰기는 라운드가 끝날 때마다 1회.** 매 베팅마다 통째로 쓰지 않는다
- **되돌릴 수 없는 사건(답 제출, 베팅 확정)은 즉시 `기록` 탭에 한 줄씩 붙인다** (리뷰 지적 반영)

### 캐시가 날아갔을 때 복구 (중요)

라운드 중간에 구글이 캐시를 비우면 그 라운드에 낸 답과 베팅이 통째로 사라질 수 있었다. 즉시 기록으로 이걸 막는다.

```
캐시에 상태가 없음
  → `게임` 탭에서 마지막 스냅샷을 읽음 (= 지난 라운드 끝 시점)
  → `기록` 탭에서 그 시점 이후 사건을 순서대로 다시 적용
  → 복구 완료. 잃는 것 없음
```

라운드당 시트 쓰기는 최대 `6모둠 × 2건 = 12회`, 0.3초 × 12 = 3.6초다. 라운드가 4분이므로 여유 있다.

### 지켜야 하는 구글 제한

| 제한 | 값 | 대응 |
|---|---|---|
| 동시 실행 | 사용자당 30개 | 폰 6대 + TV 1대 = 7 — 여유 있음 |
| 함수 실행 시간 | 6분 | 한 요청이 1초 안에 끝나므로 무관 |
| 잠금 대기 | 지정한 만큼 | 10초 대기 후 실패 시 화면에 "다시 눌러주세요" |
| 캐시 값 크기 | 100KB | 상태 JSON을 15KB 이하로 유지 (힌트 문구는 번호로만 저장) |
| 하루 실행 횟수 | 소비자 계정 기준 넉넉 | 한 반 45분 × 3.5회/초 ≈ 9,000회 — 여유 |

## 6. 게임 규칙 알고리즘 (서버 전용)

### 6-1. 정답 순위 확정 + 이동 역산

```
1) 동물 8마리에 1~8등을 무작위 배정   → truth[]
2) 마지막 라운드 R_end 를 5 또는 6 중 무작위 선택 (학생에게 비공개)
3) 각 동물의 총 이동 칸수 목표 정하기
     1등        : 10칸을, R_end - 1 라운드에 도달
     2등, 3등   : 10칸을, R_end 라운드에 도달
     4~8등      : R_end 끝에 9, 8, 7, 6, 5칸 (순위 순서대로)
4) 각 동물의 총 칸수를 라운드 수만큼 0~3 사이 값으로 쪼갬
     - 매 라운드 합이 목표와 맞아야 함
     - 앞 라운드에 0~2가 많이, 뒤 라운드에 3이 나오도록 치우치게 (역전 연출)
5) 중간 순서는 뒤집혀도 됨. 최종 도착 순서만 truth[]와 일치하면 통과
6) 검산: 모든 라운드 이동값이 0~3인지, 최종 위치 순서가 truth[]와 같은지
     → 실패 시 3)부터 다시 (최대 50회, 그래도 실패하면 오류)
```

**1차시(1~3라운드)에는 아무도 골인하지 않는다** — 3라운드까지 최대 9칸이므로 자연히 보장된다.

### 6-2. 힌트 생성 + 검산

- 힌트 문구는 시트 `힌트문구` 탭에서 읽는다. 문장 틀은 고정, 등장인물(A~H)만 매 판 바뀐다.
- 모든 힌트는 `truth[]` 기준으로 **참**이어야 한다. 생성 시 참인 것만 만든다.
- 난이도별 정보량:

| 난이도 | 힌트 성격 | 예시 |
|---|---|---|
| 어려움 | 순위를 못 박음 | "B는 최종 1등입니다", "C는 3등 안에 듭니다" |
| 중간 | 둘을 비교 | "A가 D보다 순위가 높습니다" |
| 쉬움 | 범위만 좁힘 | "H는 5등 이하입니다", "G는 1·2·3등이 아닙니다" |

- **풀 크기: 난이도별 최소 6개** (감독 단계에서 확정). 한 모둠이 6라운드 내내 같은 난이도를 고를 수 있으므로, 중복 없이 6개를 줄 수 있어야 한다. 힌트문구 탭의 종류는 난이도별 3종뿐이므로 **같은 틀을 다른 동물에 적용해** 6개를 만든다. 예: "B는 최종 1등입니다" / "F는 최종 5등입니다" — 같은 틀, 다른 대상.
- **검산**: 게임이 끝날 때까지 전 모둠에 뿌려질 힌트를 다 합쳤을 때, 8마리 중 1·2·3등이 유일하게 결정되는지 확인한다. 안 되면 어려움 힌트를 하나 더 끼워 넣는다.
- 같은 모둠에 같은 힌트를 두 번 주지 않는다.

### 6-3. 배당률

```
배당률(동물) = (전체 동물 총 베팅 코인 + 시드 총합) / (그 동물 베팅 코인 + 시드)
시드 = 동물당 15코인   ← 리뷰 반영 (PDF는 5)
소수 둘째 자리까지 표시
```

**시드를 5에서 15로 올린 이유**: 6모둠 × 6라운드 × 3코인 = 최대 108코인이 풀에 들어온다. 시드가 5면 아무도 안 건 동물 배당이 `(108+40)/5 = 29.6배`가 되어, 3코인 찍어 맞힌 모둠이 6라운드 내내 성실히 추론한 모둠을 한 방에 뒤집는다. **추론 게임이 복권이 된다.** 시드 15면 최대 배당이 `(108+120)/15 = 15.2배`로 눌려 정보 우위가 운보다 커진다.

`설정` 탭 값이므로 첫 수업 후 조정한다. 너무 밋밋하면 낮추고, 여전히 튀면 올린다.

**정산은 최종 배당률만 쓴다** (선생님 결정 — `01-prd.md §6-2` 참조). 다만 나중에 라운드별 보너스나 베팅 시점 고정으로 바꿀 수 있게, `bets`에 **라운드 번호를 처음부터 남긴다.**

### 6-4. 베팅 검증 (서버에서 막는다)

- 한 라운드에 한 모둠은 **최대 3코인**
- 보유 코인을 넘길 수 없음
- 이미 확정한 라운드에 다시 베팅 불가
- 베팅 마감(타이머 종료) 후 도착한 요청은 거부

### 6-5. 정산

```
모둠 획득 = Σ (그 동물에 건 코인 × 그 동물 최종 배당률 × 배율)
배율: 1등 100% / 2등 70% / 3등 50% / 4~8등 0% (건 코인 소멸)
최종 코인 = 남은 보유 코인 + 획득
```

## 7. 타이머

- 문제 풀이 **90초** → 모둠 토론 **180초** → 베팅 **60초** (`설정` 탭에서 바꿀 수 있음)
- 라운드 하나 = 이동 20초 + 90 + 180 + 60 ≈ **6분** (전환 포함 약 7분)

### 왜 토론을 따로 두는가 (감독 단계에서 추가)

처음 설계에는 문제 풀이 다음이 바로 베팅이었다. 그러면 **힌트를 받고 이야기할 시간이 어디에도 없다** — 베팅 60초 안에 토론까지 하라는 셈이 된다. 이 도구의 목적이 "모둠이 단서를 놓고 이야기하는 것"이므로, 토론을 정식 단계로 만든다.

토론 단계에서는 힌트 탭이 열리고 **베팅은 잠겨 있다.** 화면을 조작할 게 없어야 학생들이 서로 본다.
- 시간은 **서버 시각 기준**. 폰 시계가 틀려도 상관없게 서버가 남은 시간을 내려준다
- 종료 시 미제출 모둠은 자동으로 오답 처리 / 베팅 0 처리
- 선생님이 라운드를 수동으로 넘길 필요 없음 (타이머 자동 마감으로 확정)

### 일시정지 (리뷰 반영)

자동 마감만 있으면 "잠깐 설명 좀 할게" 같은 순간에 손쓸 방법이 없다. 교사 화면에 `⏸ 일시정지` 하나를 둔다.

```
일시정지 누름  → state.pausedAt = 지금 시각, phase는 그대로
                → 남은 시간 계산이 멈춤 (학생 화면 타이머도 멈춤)
                → 학생 화면에 "선생님이 잠시 멈췄어요" 표시
다시 누름      → phaseEndsAt += (지금 - pausedAt)
                → 멈춘 지점의 남은 시간부터 이어감
```

일시정지 중에는 답 제출·베팅이 거부된다 (`PAUSED`). 자동 마감 방침은 그대로 두고 비상구만 남기는 것이다.

---

## 8. 화면 갱신 방식

| 화면 | 간격 | 받는 내용 |
|---|---|---|
| 교사 TV | 2초 | 전체 상태 (정답 순위 포함, 단 정산 전엔 화면에 안 그림) |
| 모둠 폰 | 2초 | 자기 모둠 상태 + 공개 정보(트랙 위치·배당률·진행 현황)만 |

버전 번호(`stateVersion`)를 같이 내려서, 안 바뀌었으면 화면을 다시 그리지 않는다.

## 9. 배포

1. 구글 드라이브 → 새 스프레드시트 생성 (이름: `와일드더비`)
2. 확장 프로그램 → Apps Script
3. `Code.gs`, `Game.gs`, `Sheet.gs`, `Teacher.html`, `Team.html` 붙여넣기
4. 배포 → 새 배포 → 웹 앱
   - 실행 계정: **나(소유자)**
   - 접근 권한: **링크가 있는 모든 사용자** ← 학생 폰이 로그인 없이 들어와야 하므로 필수
5. 발급된 주소 두 개로 씀
   - 교사: `<주소>?role=teacher`
   - 학생: `<주소>` (모둠 접속 화면)

> ⚠️ 코드를 고칠 때마다 **"배포 관리 → 편집 → 새 버전"** 으로 다시 배포해야 반영된다. 이걸 안 하면 옛날 화면이 뜬다. 수업 전 반드시 확인.

## 10. 파일 구성

```
Code.gs        doGet 라우팅, GameGateway (화면이 부르는 7개 함수)
Game.gs        게임 규칙 — 순위·이동 역산·힌트 생성/검산·배당률·베팅검증·정산
Sheet.gs       시트 읽기·쓰기, 캐시, 잠금
Config.gs      상수 (시드 코인, 배율, 타이머 초, 트랙 칸수)
Teacher.html   교사 화면 (시작 / 진행 / 정산)
Team.html      모둠 화면 (접속 / 문제 / 힌트 / 베팅)
Shared.html    공통 CSS + 폴링 함수 (HtmlService include로 끼워 넣음)
```
