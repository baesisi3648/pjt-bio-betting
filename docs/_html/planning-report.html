1. 처음 요청과 다시 정리한 문제

처음 요청 (PDF 기준)

"더 지니어스의 '사기경마' 같은 베팅 게임을 구글 앱스 스크립트로 만들고 싶다. 동물 8마리가 달리고, 문제를 맞히면 난이도에 따라 순위 힌트를 받고, 모둠이 코인을 베팅해서 1·2·3등을 맞히면 이긴다."

다시 정리한 한 줄 문제

단원 마무리 복습 시간을, 모둠이 단서를 모아 서로 이야기하는 시간으로 바꾸기.

왜 바뀌었나

기획 대화에서 선생님이 꼽은 답답함은 세 가지였다 — "복습이 지루하다", "생각하는 수업을 하고 싶다", "문제를 재밌게 풀게 하고 싶다". 그리고 성공의 모습은 "조용하던 애들이 말한다" 와 "매번 써도 안 질린다" 였다.

즉 이 도구의 목적은 문제를 많이 풀리는 것이 아니다. 문제 풀이는 힌트를 얻는 수단이고, 진짜 수업이 일어나는 곳은 힌트를 받은 뒤 모둠이 머리를 맞대는 2~3분이다. 이 관점이 아래 모든 결정의 기준이 된다.

6. 원본 PDF에서 뒤집는 것 (중요)

PDF의 프로토타입 코드에는 게임을 무너뜨리는 문제가 있어 아래를 명시적으로 바꾼다.

(1) 말 이동은 랜덤이 아니라 역산이다 — 반드시

PDF 코드는 정답 순위를 랜덤으로 정해두고, 말 이동은 그와 무관하게 매 라운드 0~3칸 난수로 굴린다. 그러면 "A가 최종 1등"이라는 힌트를 뿌려놓고 A가 5등으로 들어오는 판이 실제로 나온다. 힌트가 거짓말이 되면 이 게임은 성립하지 않는다.

→ 정답 순위를 먼저 확정하고, 그 순위대로 도착하도록 각 동물의 라운드별 이동 칸수를 미리 쪼개 놓는다. 중간 순서는 뒤집혀도 되지만(연출), 최종 도착 순서는 정답 순위와 100% 일치한다.

(2) 총 라운드 수를 반쯤 고정한다

PDF는 "3마리가 골인하면 종료"라 몇 라운드에 끝날지 모른다. 2차시 수업에 맞추려면 예측 가능해야 하므로 게임 시작 시 마지막 라운드를 5 또는 6 중 하나로 몰래 정한다. 선생님 화면에는 보이고 학생 화면에는 안 보인다. 언제 끝날지 모르는 긴장은 남고, 수업 시간은 지켜진다.

(3) 힌트는 만든 뒤 검산한다

힌트 전부가 정답 순위 기준으로 참이어야 하고, 게임이 끝날 때까지 모둠들이 받은 힌트를 다 합치면 1·2·3등을 좁힐 수 있어야 한다. 생성 직후 기계가 확인하고, 조건을 못 맞추면 다시 생성한다.

(4) 라운드당 최대 3코인 제한은 실제로 강제한다

PDF 코드는 베팅 버튼을 무한정 누를 수 있다. 라운드당 3코인, 보유 코인 초과 불가를 서버에서 막는다.

(5) 정산을 실제로 계산한다

PDF 코드에는 정산 계산이 아예 없다. 1등 100% / 2등 70% / 3등 50%, 4~8등에 건 코인은 소멸 — 이 규칙대로 최종 화면에서 계산해 보여준다.

6-2. 리뷰에서 지적됐으나 그대로 두기로 한 것

배당률은 최종 배당률 하나만 쓴다 (선생님 결정)

리뷰에서 이런 지적이 나왔다 — 최종 배당률만 쓰면 1라운드에 아무도 안 볼 때 건 모둠과 6라운드에 골인 순서 다 보고 건 모둠이 같은 돈을 받는다. 그러면 "먼저 알아내면 유리하다"는 전제가 약해지고, 코인을 끝까지 쥐고 있다가 마지막에 몰빵하는 게 유리해진다.

그래도 PDF 규칙(최종 배당률)을 유지하기로 했다. 규칙이 단순해야 학생에게 설명이 되고, 실제 경마도 이 방식이다.

대신 첫 수업에서 이걸 본다: 모둠들이 초반 라운드에 코인을 안 쓰고 버티는가? 그러면 다음 중 하나로 조정한다.

  • (가) 라운드별 보너스 배율 — 1라운드에 건 코인은 ×1.5, 6라운드는 ×1.0 (설정 탭 값으로 뺄 수 있게)
  • (나) 라운드당 최소 1코인 베팅 강제
  • (다) 베팅 시점 배당률 고정으로 전환 (데이터 구조 변경 필요 → 그때 결정)

이 조정 여지를 위해 bets 자료에 베팅한 라운드 번호는 처음부터 남겨둔다. 나중에 (가)나 (다)로 갈 때 과거 판을 다시 계산할 수 있다.

문제

시트 읽기·쓰기는 한 번에 0.5~2초 걸린다. 폰 6대 + TV 1대가 2초마다 상태를 물으면 초당 3.5회 요청이고, 매번 시트를 읽으면 줄이 밀린다.

해법

읽기 요청 들어옴
  → 임시보관함(CacheService)에 게임 상태 JSON이 있나?
      있음 → 그대로 반환 (0.05초)  ★ 거의 모든 요청이 여기
      없음 → 시트에서 읽어 임시보관함에 넣고 반환 (1~2초, 판당 몇 번뿐)

쓰기 요청 (베팅·답 제출·라운드 넘김)
  → 잠금장치 획득 (최대 10초 대기)
  → 임시보관함의 상태를 고쳐 다시 넣음
  → ★ 되돌릴 수 없는 사건은 `기록` 탭에 한 줄 즉시 추가 (0.2~0.4초)
  → 라운드가 끝나면 상태 전체를 `게임` 탭에 저장
  → 잠금 해제
  • 게임 상태 JSON 하나를 통째로 캐시에 넣는다 (크기 약 5~15KB, 캐시 한도 100KB 안쪽)
  • 상태 전체 쓰기는 라운드가 끝날 때마다 1회. 매 베팅마다 통째로 쓰지 않는다
  • 되돌릴 수 없는 사건(답 제출, 베팅 확정)은 즉시 기록 탭에 한 줄씩 붙인다 (리뷰 지적 반영)

캐시가 날아갔을 때 복구 (중요)

라운드 중간에 구글이 캐시를 비우면 그 라운드에 낸 답과 베팅이 통째로 사라질 수 있었다. 즉시 기록으로 이걸 막는다.

캐시에 상태가 없음
  → `게임` 탭에서 마지막 스냅샷을 읽음 (= 지난 라운드 끝 시점)
  → `기록` 탭에서 그 시점 이후 사건을 순서대로 다시 적용
  → 복구 완료. 잃는 것 없음

라운드당 시트 쓰기는 최대 6모둠 × 2건 = 12회, 0.3초 × 12 = 3.6초다. 라운드가 4분이므로 여유 있다.

6. 게임 규칙 알고리즘 (서버 전용)

6-1. 정답 순위 확정 + 이동 역산

1) 동물 8마리에 1~8등을 무작위 배정   → truth[]
2) 마지막 라운드 R_end 를 5 또는 6 중 무작위 선택 (학생에게 비공개)
3) 각 동물의 총 이동 칸수 목표 정하기
     1등        : 10칸을, R_end - 1 라운드에 도달
     2등, 3등   : 10칸을, R_end 라운드에 도달
     4~8등      : R_end 끝에 9, 8, 7, 6, 5칸 (순위 순서대로)
4) 각 동물의 총 칸수를 라운드 수만큼 0~3 사이 값으로 쪼갬
     - 매 라운드 합이 목표와 맞아야 함
     - 앞 라운드에 0~2가 많이, 뒤 라운드에 3이 나오도록 치우치게 (역전 연출)
5) 중간 순서는 뒤집혀도 됨. 최종 도착 순서만 truth[]와 일치하면 통과
6) 검산: 모든 라운드 이동값이 0~3인지, 최종 위치 순서가 truth[]와 같은지
     → 실패 시 3)부터 다시 (최대 50회, 그래도 실패하면 오류)

1차시(1~3라운드)에는 아무도 골인하지 않는다 — 3라운드까지 최대 9칸이므로 자연히 보장된다.

6-2. 힌트 생성 + 검산

  • 힌트 문구는 시트 힌트문구 탭에서 읽는다. 문장 틀은 고정, 등장인물(A~H)만 매 판 바뀐다.
  • 모든 힌트는 truth[] 기준으로 참이어야 한다. 생성 시 참인 것만 만든다.
  • 난이도별 정보량:
난이도힌트 성격예시
어려움순위를 못 박음"B는 최종 1등입니다", "C는 3등 안에 듭니다"
중간둘을 비교"A가 D보다 순위가 높습니다"
쉬움범위만 좁힘"H는 5등 이하입니다", "G는 1·2·3등이 아닙니다"
  • 풀 크기: 난이도별 최소 6개 (감독 단계에서 확정). 한 모둠이 6라운드 내내 같은 난이도를 고를 수 있으므로, 중복 없이 6개를 줄 수 있어야 한다. 힌트문구 탭의 종류는 난이도별 3종뿐이므로 같은 틀을 다른 동물에 적용해 6개를 만든다. 예: "B는 최종 1등입니다" / "F는 최종 5등입니다" — 같은 틀, 다른 대상.
  • 검산: 게임이 끝날 때까지 전 모둠에 뿌려질 힌트를 다 합쳤을 때, 8마리 중 1·2·3등이 유일하게 결정되는지 확인한다. 안 되면 어려움 힌트를 하나 더 끼워 넣는다.
  • 같은 모둠에 같은 힌트를 두 번 주지 않는다.

6-3. 배당률

배당률(동물) = (전체 동물 총 베팅 코인 + 시드 총합) / (그 동물 베팅 코인 + 시드)
시드 = 동물당 15코인   ← 리뷰 반영 (PDF는 5)
소수 둘째 자리까지 표시

시드를 5에서 15로 올린 이유: 6모둠 × 6라운드 × 3코인 = 최대 108코인이 풀에 들어온다. 시드가 5면 아무도 안 건 동물 배당이 (108+40)/5 = 29.6배가 되어, 3코인 찍어 맞힌 모둠이 6라운드 내내 성실히 추론한 모둠을 한 방에 뒤집는다. 추론 게임이 복권이 된다. 시드 15면 최대 배당이 (108+120)/15 = 15.2배로 눌려 정보 우위가 운보다 커진다.

설정 탭 값이므로 첫 수업 후 조정한다. 너무 밋밋하면 낮추고, 여전히 튀면 올린다.

정산은 최종 배당률만 쓴다 (선생님 결정 — 01-prd.md §6-2 참조). 다만 나중에 라운드별 보너스나 베팅 시점 고정으로 바꿀 수 있게, bets에 라운드 번호를 처음부터 남긴다.

6-4. 베팅 검증 (서버에서 막는다)

  • 한 라운드에 한 모둠은 최대 3코인
  • 보유 코인을 넘길 수 없음
  • 이미 확정한 라운드에 다시 베팅 불가
  • 베팅 마감(타이머 종료) 후 도착한 요청은 거부

6-5. 정산

모둠 획득 = Σ (그 동물에 건 코인 × 그 동물 최종 배당률 × 배율)
배율: 1등 100% / 2등 70% / 3등 50% / 4~8등 0% (건 코인 소멸)
최종 코인 = 남은 보유 코인 + 획득

7. 타이머

  • 문제 풀이 90초 → 모둠 토론 180초 → 베팅 60초 (설정 탭에서 바꿀 수 있음)
  • 라운드 하나 = 이동 20초 + 90 + 180 + 60 ≈ 6분 (전환 포함 약 7분)

왜 토론을 따로 두는가 (감독 단계에서 추가)

처음 설계에는 문제 풀이 다음이 바로 베팅이었다. 그러면 힌트를 받고 이야기할 시간이 어디에도 없다 — 베팅 60초 안에 토론까지 하라는 셈이 된다. 이 도구의 목적이 "모둠이 단서를 놓고 이야기하는 것"이므로, 토론을 정식 단계로 만든다.

토론 단계에서는 힌트 탭이 열리고 베팅은 잠겨 있다. 화면을 조작할 게 없어야 학생들이 서로 본다.

  • 시간은 서버 시각 기준. 폰 시계가 틀려도 상관없게 서버가 남은 시간을 내려준다
  • 종료 시 미제출 모둠은 자동으로 오답 처리 / 베팅 0 처리
  • 선생님이 라운드를 수동으로 넘길 필요 없음 (타이머 자동 마감으로 확정)

일시정지 (리뷰 반영)

자동 마감만 있으면 "잠깐 설명 좀 할게" 같은 순간에 손쓸 방법이 없다. 교사 화면에 ⏸ 일시정지 하나를 둔다.

일시정지 누름  → state.pausedAt = 지금 시각, phase는 그대로
                → 남은 시간 계산이 멈춤 (학생 화면 타이머도 멈춤)
                → 학생 화면에 "선생님이 잠시 멈췄어요" 표시
다시 누름      → phaseEndsAt += (지금 - pausedAt)
                → 멈춘 지점의 남은 시간부터 이어감

일시정지 중에는 답 제출·베팅이 거부된다 (PAUSED). 자동 마감 방침은 그대로 두고 비상구만 남기는 것이다.

6. 어긋났을 때

상황어떻게 되나
모둠 폰이 끊김다시 접속하면 그대로 복구. 진행 중이던 라운드는 남은 시간부터 (점유가 없어 막히지 않음)
선생님이 잠깐 멈춰야 함⏸ 일시정지 — 타이머가 멈추고 학생 화면도 잠긴다. 다시 누르면 남은 시간부터
모둠이 문제를 안 냄90초 뒤 오답 처리, 힌트 없음, 게임은 진행
모둠이 베팅을 안 함60초 뒤 베팅 0으로 마감, 코인은 그대로 남음
남의 모둠 암호를 알아냄막을 방법 없음 — 암호는 종이로만, 모둠장에게만 전달 (운영으로 대응)
문제가 모자람시작 전에 경고. 그래도 시작하면 앞 라운드 문제를 다시 냄

두 가지 일을 한다.

  1. 즉시 기록 — 답 제출과 베팅 확정이 일어나는 그 순간 한 줄이 붙는다. 라운드 끝까지 안 기다린다
  2. 복구 재료 — 캐시가 날아가면 게임 탭의 마지막 스냅샷을 읽고, 그 뒤 번호가 큰 사건들을 순서대로 다시 적용해 원상 복구한다

종류는 answer / bet / round_start / pause 넷.

한 반 한 판이 끝나면 최대 6모둠 × 2건 × 6라운드 = 72줄. 학기 내내 쌓으면 수천 줄이 되므로, 끝난 판은 학기말에 다른 시트로 옮기거나 지운다 (정리 안 하면 판 만들기가 느려진다).

  • 이동은 CSS transition 0.6s만. 복잡한 연출은 이번 범위 밖

4-2. 배당률 전광판 (TV 전용)

동물걸린 코인배당률
🐆 치타122.14배
🦁 사자35.80배

  • 값이 바뀐 줄은 0.4초 동안 배경이 잠깐 밝아진다 (뭐가 움직였는지 보이게)
  • 코인이 많이 걸린 순서로 정렬하지 않는다 — 동물 순서 고정. 순서가 바뀌면 눈이 못 따라감

4-3. 모둠 현황 (TV 전용)

1모둠 미토콘드리아  ✅ 제출   💰 확정
2모둠 엽록체        ⏳ 푸는중  ⏳
  • 완료 --ok, 대기 --wait
  • 내용은 절대 안 보인다 — 뭘 골랐는지, 맞았는지는 표시하지 않는다

4-4. 난이도 고르기 (폰 전용)

  • 한 번 고르면 그 라운드에는 못 바꿈 — 누르기 전 확인 한 번 받는다

  • 난이도 색 왼쪽 띠

  • 3개를 다 쓰면 나머지 +가 흐려짐
  • 확정 버튼은 --gold, 누르면 되돌릴 수 없다는 확인을 한 번 받는다
  • 확정 후에는 전체가 회색으로 잠기고 "확정됨" 표시

4-7. 타이머

  • TV: 우상단 64px 숫자. 10초 남으면 --goal로 바뀌고 1초마다 살짝 커진다
  • 폰: 화면 맨 위 얇은 막대가 줄어드는 방식 (숫자는 작게 옆에)
  • 소리는 이번 범위 밖 (Should로 미뤄둠)

5. 지켜야 할 것

  • 버튼은 최소 44×44px (폰), 88px 세로 (주요 동작)
  • 누르면 0.1초 안에 눈에 보이는 반응이 있어야 한다. 서버 응답이 늦어도 버튼은 즉시 눌린 티를 낸다
  • 서버를 기다리는 동안 같은 버튼을 두 번 못 누르게 잠근다
  • 오류 메시지는 뭘 하라는지 적는다: ❌ "오류 발생" → ⭕ "베팅 시간이 지났어요. 다음 라운드를 기다려주세요"

S1. 교사 — 시작 화면

하는 일: 판을 새로 만들거나, 지난 시간 판을 이어받는다.

Must 기능: M1

보이는 것

  • 제목 "🧬 와일드 더비"
  • 탭 두 개: 새 판 만들기 / 판 코드로 이어하기
  • [새 판 만들기]
    • 반 이름 입력 (예: 2학년 3반)
    • 단원 고르기 (드롭다운 — 문제 탭의 A열에서 자동으로 목록을 뽑음)
    • 모둠 수 고르기 (2~8)
    • 모둠 이름 입력칸 (모둠 수만큼 생김. 비우면 1모둠, 2모둠…)
    • 판 만들기 버튼
  • [판 코드로 이어하기]
    • 판 코드 4자리 입력 + 이어하기 버튼
    • 아래에 최근 판 목록 (반 이름 / 만든 날짜 / 몇 라운드까지 갔는지 / 끝났는지)

판을 만든 직후 보이는 것 (이게 제일 중요)

학생 주소    ...exec      ← 아주 크게 (QR은 이번 범위 밖 — 외부 라이브러리 금지 원칙)

모둠별 암호 (모둠장에게만 알려주세요)
  1모둠 미토콘드리아  4821
  2모둠 엽록체        1937
  ...
                      [인쇄하기]  [진행 화면으로]

필요한 데이터: 문제 탭 단원 목록, 동물 탭, 설정 탭

막아야 하는 것

  • 문항 부족: "유전 단원 — 어려움 4문항 부족(2/6). 그래도 시작할까요?" → 계속/취소

  • 힌트문구 탭에 {X} 자리표시가 깨짐: 시작 불가, 어느 줄인지 알려줌
  • 모둠 이름 중복: 뒤에 번호 자동으로 붙임

비었을 때: 이어하기 목록이 비면 "아직 만든 판이 없어요. 새 판을 만들어 보세요."

S3. 교사 — 정산 화면

하는 일: 정답 공개하고 우승 모둠을 발표한다. 수업의 절정.

Must 기능: M13

보이는 순서 (선생님이 한 단계씩 넘김 — 한 번에 다 보여주면 김빠짐)

1단계  최종 순위 공개
       🥇 1등 호랑이(C)   🥈 2등 치타(A)   🥉 3등 타조(F)
       (4~8등도 아래에 작게)

2단계  모둠별 계산 내역
       1모둠 미토콘드리아
         치타(2등)에 4코인 × 2.14배 × 70% =  5.9 → 6코인
         사자(6등)에 2코인                  =  0코인
         남은 코인 8 + 획득 6              = 14코인

3단계  최종 순위 발표
       🏆 3모둠 리보솜  27코인
          1모둠 미토콘드리아 14코인
          ...

추가로: 이번 게임 문제 다시보기 — 라운드별 문제·정답·해설을 띄운다. 오답 짚어주는 용도. (문제·정답·해설은 이미 시트에 있으므로 만들기 부담 작음)

필요한 데이터: 게임 상태 전체 + 문제 탭 해설

S4. 모둠 — 접속 화면

하는 일: 우리 모둠으로 들어간다.

Must 기능: M5

단계 3개 (한 화면에 하나씩)

1) 판 코드 4자리        [ 2 H 4 K ]
2) 우리 모둠 고르기      1모둠 ● / 2모둠 ● / 3모둠 ●   (전부 선택 가능)
3) 암호 4자리           [ 4 8 2 1 ]

접속 점유는 두지 않는다 (리뷰 반영). 처음 설계에는 "다른 폰이 잡은 모둠은 회색"이 있었는데, 그러면 새로고침한 폰이 자기 자신 때문에 재접속을 못 한다. 수업 중 이게 터지면 그 모둠은 게임에서 이탈한다.

→ 암호만 맞으면 몇 대든 들어온다. 모둠이 폰 2대를 쓰고 싶을 수도 있고, 어차피 방어선은 암호다.

막아야 하는 것

  • 없는 판 코드: "그런 판이 없어요. 칠판의 코드를 다시 확인해주세요"
  • 이미 끝난 판: "이 판은 이미 끝났어요"
  • 암호 틀림: "암호가 달라요. 모둠장에게 확인해주세요" — 잠금은 두지 않고 시도마다 1초씩 지연만 준다 (모둠 단위로 잠그면 장난치는 학생이 남의 모둠을 계속 잠글 수 있다)
  • 새로고침·재접속: 같은 셋을 다시 넣으면 그대로 복구 (힌트·코인 유지)

주의: 학생 이름이나 학번은 받지 않는다.

  • 제출도 한 번만. 제출 후 잠김

5. 동시성

function withLock(fn) {
  var lock = LockService.getScriptLock();
  if (!lock.tryLock(10000)) return { ok:false, error:'LOCK_TIMEOUT', message:'잠시 후 다시 눌러주세요' };
  try { return fn(); } finally { lock.releaseLock(); }
}

상태를 바꾸는 모든 함수는 withLock 안에서 돈다. 읽기만 하는 getState는 잠금 없이.

읽기-수정-쓰기는 반드시 잠금 안에서 한 덩어리로. 잠금 밖에서 읽고 안에서 쓰면 6모둠 동시 베팅에 코인이 어긋난다.

09. 쓰는 사람

한 줄

  • 새 도구를 만들 의지는 있지만, 수업 준비 시간은 늘 부족

장면

유전 단원 진도를 다 뺐다. 다음 시간이 마무리 차시인데, 프린트 나눠주고 문제 풀리면 어차피 앞자리 몇 명만 손 든다. 뒤에 앉은 애들은 엎드리거나 딴짓한다. 뭔가 다르게 해보고 싶은데, 카훗은 이미 몇 번 써서 애들도 시큰둥하고 결국 빠른 애가 다 먹는다.

한 줄

장면

2라운드에 어려움을 골라서 맞혔다. "사자는 1·2·3등 안에 반드시 듭니다"가 떴다. 1라운드에 받은 "치타가 늑대보다 순위가 높습니다"랑 합쳐보는데, 옆 모둠이 갑자기 사자에 3코인을 몰아서 사자 배당률이 뚝 떨어진다. "야 쟤네도 알고 있나 본데?" "그럼 우리는 치타에 걸자, 아직 배당 좋아." 평소 말 없던 애가 "근데 거북이가 아까부터 계속 3칸씩 가는데" 한다.

  5. 같은 난이도를 고른 모둠에 같은 문제를 주는 게 맞나 — 옆 모둠 답을 베낄 수 있다 (같은 문제로 가기로 결정. 심하면 전환)

C1. "먼저 알아내면 유리하다"가 정산 규칙에 의해 지워진다

어디: 02-trd.md §6-5, 01-prd.md §6-(5), 04-database.md §5

기획 전체가 이 전제 위에 서 있다 — "1·2·3등을 빨리 알아내면 남보다 먼저 그 동물에 많이 걸어서 코인을 더 얻는다" (PDF 원문). 그런데 정산식은 이렇다.

획득 = 건 코인 × 그 동물의 최종 배당률 × 배율

최종 배당률 하나만 쓴다. 그러면 1라운드에 아무도 안 볼 때 치타에 3코인 건 모둠과, 6라운드에 다 알고 나서 치타에 3코인 건 모둠이 정확히 같은 돈을 받는다. 오히려 늦게 건 쪽이 정보가 확실하니 유리하다.

즉 일찍 추론할 이유가 없다. 마지막 라운드까지 코인을 쥐고 있다가 골인 순서 보고 몰빵하는 게 최적 전략이 된다. 힌트도, 문제 풀이도, 눈치싸움도 전부 의미가 없어진다.

실제 경마의 파리뮤추얼이 이 방식인 건 맞다. 하지만 경마는 배당률을 보고 거는 게임이고, 이건 정보를 먼저 얻는 게임이다. 규칙을 그대로 가져오면 목적과 어긋난다.

고치는 법: 베팅을 확정하는 그 순간의 배당률을 고정한다. 1라운드에 아무도 안 건 동물에 걸면 20배로 고정되고, 나중에 다들 몰려서 2배로 떨어져도 그 모둠은 20배를 받는다. 이러면 "먼저 알아낸 보상"이 숫자로 나타난다.

04-database.md의 bets 구조를 {"A": 2} 에서 {"A": {"coins":2, "odds":20.4}} 로 바꿔야 한다.

C2. 접속 점유 판정이 문서 안에서 서로 모순된다

어디: 06-screens.md S4 vs 08-test-plan.md B1

문서뭐라고 썼나
06-screens S4"다른 폰이 잡은 모둠은 회색 → TEAM_TAKEN"
08-test-plan B1"폰 새로고침 → 재입력하면 그대로 복구"

새로고침하면 그 모둠은 이미 "잡혀 있는" 상태다. 그러면 자기 자신 때문에 재접속이 막힌다. 수업 중에 이게 터지면 그 모둠은 게임에서 이탈한다.

고치는 법 (둘 중 하나)

  • (가) 점유를 아예 없앤다 — 암호만 맞으면 몇 대든 들어옴. 모둠이 폰 2대를 쓰고 싶을 수도 있고, 어차피 암호가 방어선이다. 이쪽을 권한다.
  • (나) 마지막 요청으로부터 30초 지나면 점유 해제. 구현이 늘고, 30초 안에 새로고침한 모둠은 여전히 막힌다.

⚠️ 중대 — 수업 중에 사고가 날 지점

C3. 캐시가 날아가면 그 라운드 베팅이 통째로 사라진다

어디: 02-trd.md §5

시트 쓰기를 "라운드 끝날 때 1회"로 몰아놨다. 성능상 옳은 결정이지만, 라운드 중간에 구글이 캐시를 비우면 그 라운드에 낸 답과 베팅이 전부 증발한다. 문서에는 "최대 1라운드 손실"이라고 한 줄 적혀 있는데, 교실에서 이건 "우리 코인 어디 갔어요"가 30명 앞에서 터지는 사고다.

고치는 법: 되돌릴 수 없는 사건(답 제출, 베팅 확정)만 기록 탭에 즉시 한 줄 추가한다. 시트에 한 줄 붙이는 건 상태 전체를 쓰는 것보다 훨씬 빠르다(0.2~0.4초). 캐시가 날아가면 마지막 스냅샷 + 그 뒤 사건들을 다시 재생해서 복구한다.

C4. 폰 1대에 4~5명 — 목적과 정면 충돌

어디: 06-screens.md S5, 09-personas.md

이 도구의 목적은 "조용하던 애들이 말한다" 다. 그런데 화면은 6인치 하나고, 그걸 든 한 명이 조작한다. 힌트를 읽는 것도, 문제를 읽는 것도 그 한 명이다. 나머지 4명은 목을 빼고 넘겨다본다. 카훗보다 나빠질 수 있다 — 카훗은 최소한 문제가 TV에 뜬다.

이건 기술로 못 푼다. 모둠마다 다른 난이도를 고르니 문제를 TV에 띄울 수도 없다.

완화 (세 개 다 해야 한다)

  1. 힌트 카드 글자를 훨씬 크게 (17px → 20px, 줄간격 1.8). 폰을 가운데 놓고 넷이 같이 읽을 수 있게
  2. Should로 미뤄둔 모둠 메모장을 Must로 올린다. 힌트를 옮겨 적으며 이야기하는 게 이 수업의 실체다
  3. 운영으로: 모둠마다 A4 한 장을 주고 힌트를 옮겨 적게 한다 (앱이 아니라 수업 설계)

C5. 선생님이 수업을 멈출 방법이 없다

어디: 03-user-flow.md §3, 02-trd.md §7

타이머 자동 마감만 있고 일시정지가 없다. 첫 수업에서 "잠깐, 이거 설명 좀 할게" 하는 순간이 반드시 온다. 학생 질문, 갑작스러운 방송, 기기 문제 — 전부 타이머가 돌아가는 중에 일어난다.

고치는 법: 교사 화면에 ⏸ 일시정지 하나. 누르면 phaseEndsAt을 미뤄놓고, 다시 누르면 남은 시간부터 이어간다. 코드 20줄이면 된다. 자동 마감 방침은 그대로 두되 비상구는 남긴다.

C6. 시드 코인 5는 배당률을 극단으로 튀게 한다

어디: 04-database.md §5, 02-trd.md §6-3

6모둠 × 6라운드 × 3코인 = 최대 108코인이 풀에 들어온다. 시드는 동물당 5, 총 40.

상황배당률
아무도 안 건 동물(108+40) / 5 = 29.6배
30코인 몰린 동물148 / 35 = 4.2배

29.6배짜리에 3코인 찍어서 우연히 맞으면 88코인이다. 6라운드 내내 성실하게 추론한 모둠을 한 방에 뒤집는다. 추론 게임이 아니라 복권이 된다.

고치는 법: 시드를 동물당 15~20으로 올린다. 그러면 최대 배당이 8~10배로 눌리고, 정보 우위가 운보다 커진다. 설정 탭 값이니 첫 수업 후 조정 가능하지만, 초기값을 5로 두면 첫 수업이 망한다.

💡 개선 제안 — 지금 안 해도 되지만 하면 좋음

C7. 접속 3단계를 모둠별 QR로 1단계로 줄이기

첫 수업 접속에 10분이 걸릴 위험을 이미 문서에 적어뒀는데, 완화책이 "미리 확인" 뿐이다. 모둠별 QR을 인쇄하면(판 코드 + 모둠 번호까지 담고, 암호만 손입력) 3단계가 1.5단계가 된다. S1 인쇄 화면에 QR을 같이 넣으면 되므로 추가 부담이 작다.

C8. 힌트를 부분만 받으면 아무도 답을 못 좁힌다

08-test-plan.md G3는 전체 힌트를 합쳤을 때 1·2·3등이 유일하게 결정되는지 검사한다. 그런데 실제로 한 모둠은 6개(라운드당 1개)만 받는다. 6개 부분 정보로 8마리 중 상위 3을 좁히는 게 가능한지는 검사하지 않는다.

고치는 법: G3를 두 단계로 나눈다.

  • G3-a: 전체 힌트로 유일 결정 (지금 있음)
  • G3-b: 어려움만 6번 고른 모둠이 받을 힌트로 1·2·3등을 좁힐 수 있는가 → 이게 안 되면 어려움을 고를 이유가 없다

C9. 같은 난이도를 고른 모둠이 같은 문제를 받는 문제

04-database.md에 이미 "아직 안 정한 것"으로 적혀 있지만, 리뷰 관점에서는 거의 확실히 문제가 된다. 5~6모둠이 한 교실에서 동시에 같은 문제를 90초 안에 푼다. 옆 모둠 소리가 다 들린다.

고치는 법: 난이도별 문제를 미리 섞어서 모둠마다 다른 번호를 배정한다. 필요 문항 수가 늘어나는 게 아니라(라운드당 난이도별 1문항이면 6모둠이 겹침), 난이도별 문항을 6개 이상 확보하면 라운드마다 모둠별로 다른 걸 줄 수 있다. → 단원당 최소 문항이 18개에서 늘어난다. 선생님 부담과 직결되므로 결정이 필요하다.

C10. 암호 3회 실패 잠금이 장난의 도구가 된다

06-screens.md S4에서 "3번 틀리면 30초 잠금"인데, 누구를 잠그는지가 안 적혀 있다. 모둠 단위로 잠그면 장난치는 학생이 남의 모둠을 계속 잠글 수 있다.

고치는 법: 잠금을 없애고 시도마다 1초씩 지연만 준다. 4자리 숫자를 손으로 찍어 맞히는 건 어차피 현실적으로 어렵고, 교실이라 물리적으로 감시된다.

더 중요한 함의

2차시 분할은 기획 대화에서 이렇게 결정됐다 — "6팀 순차 진행이면 라운드당 10분, 50분에 3라운드밖에 못 돈다." 그런데 이후 모둠 폰 동시 진행으로 바꾸면서 라운드가 4분이 됐다. 그러면:

규칙 설명   8분
6라운드 × 4분 = 24분
정산        8분
─────────────────
합계       40분   → 1차시에 전부 끝난다

2차시 분할을 만든 이유가 사라졌는데 결정은 그대로 남아 있다. 그리고 2차시 분할 때문에 M1(판 코드 이어하기)·P1-R2-T3(사건 기록 복구)·B5(이어하기 검사)라는 적지 않은 구현량이 붙어 있다.

영향받는 문서: 01-prd §2·§4(M1), 02-trd §5, 03-user-flow §1·§2, 06-tasks P1-R2-T3·P6-T2, 08-test-plan B5

필요한 것: 사용자 결정. 아래 세 갈래 중 하나.

  1. 2차시 유지 — 그러면 라운드당 12분이 되도록 모둠 토론 시간을 별도 단계로 명시해야 한다 (지금은 토론 시간이 어느 단계에도 없다)
  2. 1차시 완결로 전환 — M1·복구 로직이 "있으면 좋은 것"으로 내려가고 구현량이 줄어든다
  3. 1차시 목표 + 2차시 대비 — 기본은 1차시 완결, 못 끝내면 이어하기. 구현은 유지하되 시간표를 다시 씀
참고: 토론 시간을 명시하는 게 기획 목적("조용하던 애들이 말한다")에는 오히려 맞다. 지금 흐름에는 힌트를 받고 이야기할 시간이 따로 잡혀 있지 않다 — 베팅 60초 안에 토론까지 하라는 셈이다.
