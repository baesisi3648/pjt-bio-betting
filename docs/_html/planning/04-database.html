2. 문제 탭 — 선생님이 채우는 곳

A 단원B 난이도C 문제D 보기1E 보기2F 보기3G 보기4H 정답I 해설
유전어려움다음 중 반성유전에 해당하는 것은?혈우병ABO식 혈액형낫모양적혈구페닐케톤뇨증1X염색체에 유전자가 있어…
유전중간사람의 성염색체 구성으로 옳은 것은?…………3
유전쉬움DNA의 기본 단위는?뉴클레오타이드아미노산포도당지방산1

규칙

  • 난이도는 쉬움 / 중간 / 어려움 세 글자 중 하나 (다르게 쓰면 무시됨)
  • 정답은 보기 번호 1~4 숫자
  • 해설은 비워도 됨 (정산 후 다시보기에만 쓰임)
  • 4지선다 고정. 주관식은 이번 범위 밖 (자동 채점이 안 되므로)

필요한 문항 수

  • 한 단원 = 최대 6라운드 × 3난이도 = 최소 18문항
  • 모둠이 같은 난이도를 겹쳐 고르면 같은 문제를 받는다 (모둠 간 형평은 유지됨)
  • 판 만들 때 부족하면 경고: "유전 단원 — 어려움 4문항 부족. 그래도 시작할까요?"

3. 힌트문구 탭 — 문장 틀

A 난이도B 종류C 문장 틀
어려움순위확정{X}는 최종 {N}등입니다.
어려움상위확정{X}는 1·2·3등 안에 반드시 듭니다.
어려움부정확정{X}는 최종 1등이 아닙니다.
중간둘비교{X}가 {Y}보다 순위가 높습니다.
중간사이끼움{X}는 {Y}보다 빠르고 {Z}보다 느립니다.
쉬움범위{X}는 {N}등 이하입니다.
쉬움제외{X}는 1·2·3등에 들지 못합니다.
쉬움둘중하나{X} 또는 {Y} 중 하나는 {N}등 안에 듭니다.
  • {X} {Y} {Z} 자리에는 동물의 표시 이름이 들어간다 (예: 치타)
  • {N}은 앱이 계산해서 채운다
  • 선생님이 문장 표현을 고쳐도 되지만 {X} 같은 자리표시는 지우면 안 됨
  • 종류(B열)는 앱이 논리를 판단하는 열쇠라 바꾸면 안 됨. 새 문장을 추가하려면 기존 종류 중 하나를 골라 쓴다

4. 동물 탭

A 코드B 이름C 그림
A치타🐆
B사자🦁
C호랑이🐯
D늑대🐺
E얼룩말🦓
F타조🦩
G개구리🐸
H거북이🐢
  • 정확히 8줄이어야 함
  • 이름과 그림은 마음대로 바꿔도 됨 — 세포소기관·효소·생태계 생물로 갈아 끼우면 단원마다 다른 테마가 된다
  • 코드(A~H)는 고정. 힌트 생성 내부에서 쓰인다
주의: 이름을 실제 달리기 속도와 무관하게 지어도 된다. 순위는 매 판 무작위라 "치타가 당연히 1등"은 성립하지 않는다. 오히려 학생이 상식으로 찍는 걸 막으려면 속도 이미지가 비슷한 것들로 채우는 게 좋다.

6. 게임 탭 — 앱이 쓰는 곳 (건드리지 말 것)

A 판코드B 반이름C 단원D 상태JSONE 만든시각F 갱신시각G 종료여부

7QMZ2학년 5반유전{...}2026-08-20 11:052026-08-20 11:52TRUE

한 반이 한 줄이다. 반이 여러 개여도 서로 안 섞인다.

중요한 항목

항목뜻
truth1등부터 8등까지 동물 코드 순서. 절대 학생 화면으로 안 나감
moves동물별 라운드 이동량 (역산으로 미리 다 정해둠)
lastRound5 또는 6. 학생 화면으로 안 나감
phasewaiting / moving / quiz / discuss / betting / paused / done
phaseEndsAt서버 시각 기준 마감 시각 (폰 시계와 무관)
pausedAt일시정지 시작 시각. null이면 진행 중
eventSeq기록 탭에 마지막으로 반영된 사건 번호. 캐시 복구의 기준점
stateVersion바뀔 때마다 +1. 화면은 이게 바뀔 때만 다시 그림
pool동물별 누적 베팅 (시드 포함) — 배당률 계산 원본
betLocked라운드별 베팅 확정 여부. 확정 후 되돌리기 불가
questionPlan판 생성 시 미리 다 정한다. 라운드×난이도마다 문항 번호 1개. 라운드마다 그때그때 뽑으면 캐시 복구 시 다른 문제가 나온다
hintPool난이도별 힌트 문장. 각 6개 이상 — 한 모둠이 6라운드 내내 같은 난이도를 골라도 중복이 안 나게
hintGiven모둠별로 이미 준 힌트 번호. 중복 지급 방지
bets는 반드시 라운드별로 나눠 저장한다. 나중에 라운드별 보너스 배율이나 베팅 시점 배당률 고정으로 바꿀 수 있게 남겨두는 것이다 (01-prd.md §6-2).

크기 관리: 힌트는 문장을 통째로 저장한다(모둠당 최대 6개). 8모둠 기준 대략 8~12KB로, 캐시 한도 100KB 안쪽이다.

7. 기록 탭 — 사건 기록 겸 복구 재료

A 번호B 판코드C 라운드D 모둠E 종류F 내용(JSON)G 시각
1262H4K31answer{"level":"어려움","choice":2,"correct":false}09:41:22
1272H4K31bet{"A":2,"C":1}09:42:10

두 가지 일을 한다.

  1. 즉시 기록 — 답 제출과 베팅 확정이 일어나는 그 순간 한 줄이 붙는다. 라운드 끝까지 안 기다린다
  2. 복구 재료 — 캐시가 날아가면 게임 탭의 마지막 스냅샷을 읽고, 그 뒤 번호가 큰 사건들을 순서대로 다시 적용해 원상 복구한다

종류는 answer / bet / round_start / pause 넷.

한 반 한 판이 끝나면 최대 6모둠 × 2건 × 6라운드 = 72줄. 학기 내내 쌓으면 수천 줄이 되므로, 끝난 판은 학기말에 다른 시트로 옮기거나 지운다 (정리 안 하면 판 만들기가 느려진다).

8. 모둠 폰에 내려보내는 것 (아주 중요)

서버는 요청자를 보고 다른 내용을 돌려준다.

// 모둠 폰이 받는 것
{
  round, lastRoundHidden: true,       // lastRound 값 자체를 안 보냄
  phase, secondsLeft,
  positions,                           // 모든 동물 위치 (공개)
  odds,                                // 배당률 (공개)
  teamProgress: [{no,name,answered,betLocked}],  // 이름과 완료여부만
  me: { no, name, coins, hints, myBets, canAnswer, canBet },
  question: { text, choices } | null   // 지금 라운드에 고른 난이도 문제만
}

절대 안 내려보내는 것: truth, moves, lastRound, 다른 모둠의 hints·pin·answered.correct, 문제 정답 번호(채점 전).

화면에서 감추는 게 아니라 응답에 담지 않는다. 브라우저 개발자 도구를 열어도 안 보인다.
