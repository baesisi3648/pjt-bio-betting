08. 확인 계획 — 뭘 어떻게 검사하나

  • 상위 문서: 02-trd, 04-database, 07-coding-convention

1. 게임이 무너지는 것부터 (제일 중요)

이 넷 중 하나라도 깨지면 수업에서 게임을 못 쓴다.

#확인할 것방법통과 기준
G1최종 도착 순서 = 정답 순위Test.gs에서 판 100개 생성 후 6라운드 다 굴려 비교100/100 일치
G2모든 힌트가 참판 100개, 생성된 힌트 전부를 정답 순위에 대조거짓 힌트 0개
G3-a전체 힌트로 1·2·3등을 좁힐 수 있다판 100개, 전체 힌트를 합쳐 8! 순열을 걸러냄1·2·3등이 유일하게 결정 100/100
G3-b어려움만 6번 고른 모둠이 좁힐 수 있다그 모둠이 받을 힌트 6개만으로 같은 검사1·2·3등을 좁힐 수 있음 100/100. 안 되면 어려움을 고를 이유가 없다 (리뷰 반영)
G4모둠 응답에 정답이 안 담김toTeamView 결과 JSON을 문자열로 만들어 검사truth·moves·lastRound 문자열 0회 등장

G1이 이 프로젝트의 최대 위험이다. PDF 원본 코드가 바로 여기서 깨져 있었다.

2. 규칙 계산

#확인할 것통과 기준
R1라운드당 3코인 초과 거부4코인 시도 → TOO_MANY_COINS
R2보유 코인 초과 거부코인 1개인데 2개 → NOT_ENOUGH_COINS
R3마감 후 베팅 거부시간 지난 뒤 → BET_CLOSED
R4확정 후 재베팅 거부두 번째 → ALREADY_BET
R5라운드당 문제 1회두 번째 제출 → ALREADY_ANSWERED
R6배당률 계산손으로 계산한 값과 소수 둘째 자리까지 일치
R7정산 계산1등 100%·2등 70%·3등 50%·나머지 0으로 손계산과 일치
R8이동값 범위모든 라운드 이동이 0~3 안
R91차시 골인 없음3라운드까지 10칸 도달 동물 0마리
R10같은 힌트 중복 지급 안 함한 모둠이 같은 문장을 두 번 안 받음

3. 동시에 몰릴 때

#상황통과 기준
C16모둠이 같은 순간 베팅 확정동물별 누적 코인 합계가 어긋나지 않음
C26모둠 동시 제출 + TV 폴링모든 요청이 10초 안에 응답
C3잠금 대기 초과LOCK_TIMEOUT이 뜨고 화면에 안내가 나옴 (조용히 실패하지 않음)
C4폰 6대 + TV 1대 2초 폴링상태 조회 평균 응답 0.3초 이하

C1은 실제 폰 6대로 "하나 둘 셋" 하고 동시에 눌러 확인한다.

4. 끊기고 복구되는 것

#상황통과 기준
B1모둠 폰 새로고침판코드+모둠+암호 재입력으로 힌트·코인 그대로. 점유 때문에 막히지 않음
B1-b같은 모둠에 폰 2대 동시 접속둘 다 들어가지고 상태가 같음 (점유를 두지 않기로 함)
B2폰 비행기모드 30초 후 복귀자동으로 상태 따라잡음
B3교사 노트북 브라우저 종료 후 재접속판 코드로 마지막 라운드 시작 시점부터 복구
B4라운드 중간에 캐시 강제 삭제 후 조회스냅샷 + 기록 탭 사건 재생으로 손실 0 — 그 라운드 답과 베팅이 전부 살아 있어야 함
B51차시 종료 → 다음 날 2차시 이어하기코인·힌트·베팅·트랙 위치 전부 그대로
B6일시정지 → 3분 후 재개멈춘 지점의 남은 시간부터 이어감. 멈춘 동안 제출은 PAUSED로 거부

B5가 이 프로젝트의 두 번째 위험이다. 2차시 분할이 안 되면 기획 전체가 무너진다.

5. 시트가 잘못됐을 때

#상황통과 기준
S1어려움 문항 2개뿐 (6 필요)판 만들기 전 경고, 계속/취소 선택 가능
S2동물 탭이 7줄시작 불가 + 어디가 문제인지 안내
S3힌트문구에서 {X}를 지움시작 불가 + 몇 번째 줄인지 안내
S4난이도를 상/중/하로 적음그 줄은 무시, 문항 수 경고에 반영
S5정답 열에 5를 적음그 줄은 무시 + 안내
S6문제 0개인 단원 선택시작 불가

6. 화면

#확인할 것통과 기준
U1교실 뒷자리 가독성8m 뒤에서 배당률 숫자가 읽힘 (실제 교실에서)
U2폰 세로 360px잘리는 부분 없음
U3버튼 두 번 누르기중복 요청 안 감
U4오류 메시지전부 "뭘 하라"까지 적혀 있음
U5색 없이도 구분흑백으로 캡처해도 정답/오답, 난이도 구분됨
U6정답 순위 실수 노출"정답 순위 보기"가 눈에 안 띄고, 열면 확인을 한 번 받음

7. 수업 전 점검표 (매 수업, 5분)

이건 코드 검사가 아니라 선생님이 수업 직전에 하는 확인이다. 이 목록을 앱 시작 화면에도 넣는다.
  • 코드를 고쳤다면 새 버전으로 재배포했는가 (제일 흔한 사고)
  • 화면 하단 배포 버전이 오늘 것인가
  • 이번 단원 문항이 18개 이상인가
  • 교사 노트북에서 학생 주소가 열리는가
  • 내 폰(학교 와이파이)에서 학생 주소가 열리는가 ← 학교망 차단 확인
  • 모둠별 암호를 인쇄했는가
  • TV에 화면이 잘리지 않고 뜨는가

8. 첫 수업에서 볼 것

첫 판은 검사가 아니라 관찰이다.

볼 것어긋나면
접속에 몇 분 걸리나10분 넘으면 1차시 라운드를 2개로 줄임
문제 90초가 맞나남으면 줄이고, 모자라면 늘림 (설정 탭에서 바로)
베팅 60초가 맞나같음
힌트로 실제 추론이 되나너무 어려우면 어려움 힌트 비중을 늘림
하위권 모둠이 포기하나포기하면 정산 규칙 완화를 재검토 (지금은 PDF 그대로)
초반에 코인을 안 쓰고 버티나최종 배당률만 쓰기로 한 결과. 다들 마지막에 몰빵하면 01-prd §6-2의 (가)~(다) 중 하나로 조정
배당률이 너무 튀나시드 15가 여전히 낮으면 20으로, 밋밋하면 10으로 (설정 탭)
폰 1대를 한 명이 독점하나독점하면 모둠 메모장을 Must로 올리거나 A4 병행을 수업 규칙으로
옆 모둠 답을 베끼나같은 문제를 주기로 한 결과. 심하면 모둠별 다른 문제 배정으로 전환 (문항 3배 필요)
조용하던 학생이 말하나이게 안 되면 기획 자체를 다시 본다
